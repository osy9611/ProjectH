# 캐릭터 스프라이트 작업 파이프라인 (흡수안)

2026-11-10, 아트 분석 스레드. 별도로 진행한 파이프라인(`ProjectH_ArtArchive/references/resonance`, 이하 "외부 파이프라인". 2026-11-11 정리 뒤 원문은 `references/resonance_pipeline/`)에서 우리 작업에 쓸 것을 골라 우리 규격에 맞게 옮겼다. 근거 분석은 [../analysis/resonance-pipeline-review.md](../analysis/resonance-pipeline-review.md)에 있다.

이 문서는 공정과 도구를 다룬다. 수치 규격(도트 배율, 캔버스, 색 수, 밝기)은 규격 문서(`character-sprite-spec.md`, `Tools/HD2D/art/spec.py`)가 정하고, 여기 나오는 새 기준값은 모두 제안이다.

## 공정

2026-11-11 사용자 결정으로 바꾼 순서다. 핵심 변경은 두 가지다.
- 캐릭터마다 시안과 가장 닮은 FFBE 맵 캐릭터 한 명을 골라, 그 실측값을 **생성 목표**로 쓴다. 이전에는 FFBE 21명의 평균과 범위를 결과 비교에만 썼다.
- 눈은 모든 캐릭터에 FFBE 7번 구조 하나를 고정하지 않는다. 캐릭터마다 레퍼런스에서 가장 닮은 눈 구조를 골라 다시 그린다.

| 단계 | 하는 일 | 끝나는 조건 | 도구 | 사람 |
|---|---|---|---|---|
| 1. 시안·브리프 | 시안을 받고 `brief.md`에 실루엣 키 3개, 키 컬러 4~6개, 버릴 디테일, 비대칭 요소를 적는다 | `brief.md` 기본·픽셀 번역 작성 | 템플릿, [concept-guide.md](concept-guide.md) | 시안 제공 |
| 2. 레퍼런스 선택 | FFBE 맵 캐릭터 22명(`references/ffbe_map_sprites/derived/ref_views/`의 정면·측면·후면)에서 시안과 닮은 후보 3명을 고른다. 기준은 체형·성별, 등신, 머리 길이와 모양, 의상 실루엣(코트·망토·치마), 소품이다. 후보마다 이유와 실측값을 나란히 보여 준다 | 사용자가 한 명 선택. `brief.md` "레퍼런스"에 이름과 목표 수치 기록 | [ffbe-body-reference.md](ffbe-body-reference.md), [data/ffbe_face_landmarks.json](data/ffbe_face_landmarks.json) | **승인 ①** |
| 3. 눈 설계 | 선택한 레퍼런스의 눈 구조(폭, 줄 수, 속눈썹·홍채·반사 위치, 두 눈 사이, 눈 시작 행, 턱→눈)를 잰다. 시안의 눈 인상과 맞지 않으면 실측표에서 더 닮은 눈을 고른다. 구조만 가져와 캐릭터 색으로 다시 그린다 | `brief.md` "눈"에 구조도(행별 색 역할)와 좌표 기록 | 좌표 스크립트(`Art/Characters/<Name>/eyes.py`) | 2와 함께 확인 |
| 4. 정면 2~3안 | 그림체 기준(PixelLab v3, 크기 52, `selective outline`)을 만들고, 시안과 함께 pro로 정면 후보를 만든다. 정리 일괄 → 눈 적용 → 목표 수치 대조 → 리뷰 보드. 필요하면 인페인트와 좌표 스크립트로 손본다 | 사용자가 한 안 승인. 목표 수치 허용 범위 안 | PixelLab, 정리 일괄, `review_board.py --ref` | **승인 ②** |
| 5. 방향 확장 | 승인된 정면을 기준으로 v3 회전해 나머지 7방향을 만든다 → 정리 일괄 | 방향 간 키 차 ≤3, 실루엣 키 유지 | PixelLab 회전, `silhouette_check.py` | **승인 ③** |
| 6. 애니메이션 | Idle부터 규격의 프레임 수로 만든다 → 정리 일괄 | 발 위치 이탈 ≤2px(제안) | PixelLab, `check_sprite.py` | 확인 |
| 7. 검사 | 규격 검사와 실루엣 검사를 모두 통과 | 두 도구 오류 0 | `check_sprite.py`, `silhouette_check.py` | |
| 8. 엔진 확인 | 낮·밤 화면을 창 없이 한 번에 찍는다 | 사용자 확인 | `build_artspec.py`, `run_artspec.ps1` | **승인 ④** |

### 레퍼런스 수치를 생성 목표로 쓰는 법

| 목표 | 레퍼런스 값 | 허용 범위(제안) | 맞추는 방법 |
|---|---|---|---|
| 키(발바닥~정수리, 장식 포함) | 실측 키 | ±2도트 | 생성 크기 지정. 벗어나면 다시 생성 |
| 머리(정수리~턱) | 실측 머리 | ±1도트 | 생성 입력 이미지의 비율. PixelLab pro는 설명의 체형 지시를 무시하고 입력 이미지 비율을 따른다. 시안 등신이 목표와 다르면 입력용 시안을 목표 등신으로 고친다 |
| 등신 | 키 ÷ 머리 | ±0.15 | 위 두 항목의 결과 |
| 정면 폭/키 | 레퍼런스 정면 폭/키 | +0.05 이내, 상한 0.78 | 머리카락·망토 폭 손 보정 |
| 눈 시작 행, 눈 크기, 턱→눈 | 3단계 구조 | 일치 | 눈 좌표 스크립트로 맞춤 |

외부 파이프라인 교훈("스타일 참조는 비율까지 끌고 간다")대로 비율은 입력 이미지로 고정하고, 그림체 기준은 그림체에만 쓴다.

### FFBE 자료를 쓰는 범위

FFBE 스프라이트는 측정해서 참고하는 데만 쓴다. PixelLab 입력 이미지(시안, 스타일, 인페인트 참고)로 넣지 않고, 픽셀을 옮겨 붙이지 않는다. 눈도 구조와 수치만 가져와 캐릭터 색으로 다시 그린다. 레퍼런스가 들어간 리뷰 보드(`--ref`)는 작업용이고 커밋하지 않는다.

### 정리 일괄

생성 결과를 받을 때마다 같은 순서로 돌린다: 셀 맞추기(`fit_to_cell.py`) → 선택적 유색 외곽선(`selout.py`) → 외톨이 픽셀 정리(`recolor_outline.py`) → 전 방향·전 프레임 공용 팔레트(`merge_colors.py`). 단계마다 `before_*` 백업과 작업 이력을 남긴다. 한 명령으로 묶는 스크립트는 이 파이프라인 작업에서 만든다.

## 리뷰

`review_board.py`로 한 장짜리 보드를 만들어 보여 준다. 이미지 한 장을 그냥 보내지 않는다.

```bash
python Tools/HD2D/art/review_board.py --name <Name> --variant A=Art/Characters/<Name> --variant B=<후보 PNG> --concept <시안> --q "망토 밑단 A/B"
```

보드 구성: 시안과 정면(×5), 모든 방향(×3), 실루엣, 1배와 게임 배율(도트 1개 = 화면 6px), 배경 4종, 수치(기준 밖은 빨강), 질문.

리뷰 순서는 실루엣 → 비율 → 얼굴 → 색 → 디테일이다. 앞 단계가 정해지기 전에는 뒤 단계 피드백을 받지 않는다. 결정은 바로 `brief.md`에 적는다.

다른 게임 스프라이트(`--ref`)가 들어간 보드는 작업용이다. 저장소에 커밋하지 않는다.

## 검사 추가분

`silhouette_check.py`는 `check_sprite.py`가 보지 않는 세 가지를 본다.

| 검사 | 제안 기준 | 근거(FFBE 22명, 바닥 그림자 제외) |
|---|---|---|
| 정면 폭/키 | ≤ 0.78 | 정면 평균 0.61, 최대 0.78 |
| 후면 폭/키 | ≤ 0.80 | 후면 평균 0.62, 90백분위 0.79 |
| 떨어진 픽셀(8연결 가장 큰 덩어리 밖) | 0 | 정면 22명 모두 0. 측면은 들고 있는 무기만 떨어짐 |
| 방향 간 키 차 | ≤ 3 | 외부 파이프라인 게이트 |

두 기준값은 규격 세션이 받아들이면 `spec.py`로 옮긴다.

## 교훈

외부 파이프라인 `CLAUDE.md`·`brief.md`에 기록된 것 중 우리에게도 해당하는 것이다.

1. **옷과 디테일은 생성 단계에서 한 번에 만든다.** 서로 다른 결과물을 이어 붙이거나 AI 편집 위에 덧칠하면 디자인이 뭉개진다. 생성 뒤에는 팔레트 교체와 눈처럼 아주 작은 픽셀만 고친다.
2. **수치 검사는 얼굴 붕괴를 못 잡는다.** 수치가 통과해도 4배 이상 확대해서, 밝은 배경에도 놓고 눈으로 본다.
3. **스타일 참조는 비율까지 끌고 간다.** 참조 캐릭터의 등신이 결과에 그대로 남았다. 비율은 참조가 아니라 입력 이미지로 고정한다.
4. **비대칭 캐릭터는 생성기가 좌우 디테일을 바꿔 그릴 수 있다.** 정면에서 무엇이 어느 쪽인지 브리프에 적고, 방향마다 확인한다.
5. **손 보정은 원본을 덮지 않는다.** 좌표 스크립트로 고치고 새 버전 폴더에 쓴다. 우리 `before_*` 백업 방식과 같다.
6. **시안의 디테일은 크기로 걸러진다.** 키 50도트에서 몸 키의 4%(2도트)보다 작은 요소는 사라지거나 노이즈가 된다. 시안 단계에서 남길 것을 고른다([concept-guide.md](concept-guide.md)).
7. **비슷한 색이 많으면 뭉개진다.** 외부 파이프라인의 시험 캐릭터는 정면 129색을 48색으로 줄여도 화면 차이가 거의 없었다.
