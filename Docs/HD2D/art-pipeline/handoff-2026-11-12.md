# 캐릭터 스프라이트 파이프라인 인계 (2026-11-12)

이 문서만 읽고 다른 PC, 다른 세션, 다른 도구에서 작업을 이어갈 수 있게 정리했다. 날짜별 상세 기록은 [Art/Characters/Hiyori/brief.md](../../../Art/Characters/Hiyori/brief.md)에 있다. [README.md](README.md)의 공정은 아직 2026-11-11판이고, 이 문서의 "개정 공정"이 반영 대기 중이다.

## 1. 결론

- **PixelLab 결과의 비율과 그리는 방식(외곽선, 명암, 안쪽 밀도)은 그림체 기준이 정한다.** 시안을 세 번 바꾸고 설명을 길게 써도 비율은 바뀌지 않았다. 그림체 기준을 바꾸자 크게 바뀌었다.
- **시안은 무엇을 그리느냐(장식, 색, 구성)만 정한다. 설명 문장은 장식 유무만 바꾼다.**
- **비율을 지키는 방법은 완성된 스프라이트를 편집 입력이나 첫 프레임으로 넣는 것뿐이었다.**
- **후처리는 쌓을수록 그림이 나빠졌다.** 행 빼기, 일괄 톤 압축, 전체 외곽선 교체, 꼬리 폭 줄이기를 거친 결과를 버리고 생성 원본으로 되돌렸다.
- Hiyori 현재 기준은 `Art/Characters/Hiyori/E_base/`(PixelLab 생성 원본 E 8방향, 셀 맞춤 + 공용 40색만)다. 애니메이션과 엔진 확인은 아직이다.

## 4. 규격 요약 (`Tools/HD2D/art/spec.py`, `Docs/HD2D/character-sprite-spec.md`)

| 항목 | 값 |
|---|---|
| 셀 | 64×80, 피벗 (32,76), 발바닥 75행 |
| 키 | 레퍼런스 값 ±2 (Hiyori: Fina 50) |
| 색 | 주인공 40, NPC 24. 8방향 공용 팔레트 |
| 알파 | 0 또는 255만 |
| 외곽선 | 검정 금지(루마 12 미만 없음), 선택적 유색 외곽선 |
| 밝기 | 루마 210 초과 1% 이하 — **근거 재확인 필요**. 강제하면 흰 옷이 회보라가 된다. 엔진 낮 캡처로 검증 전까지 강제하지 않는다 |
| 정면 폭/키 | 0.78 이하, 후면 0.80 이하 (FFBE 최대에서 나온 제안값) |
| 방향 | FR, FLS, LS, BLS, BK, BRS, RS, FRS (화면 기준: LS = 화면 왼쪽을 봄 = PixelLab west) |

## 5. 개정 공정 (README 반영 대기)

| 단계 | 할 일 | 산출물 | 승인 |
|---|---|---|---|
| 1 시안·브리프 | 실루엣 키, 키 컬러, 버릴 디테일, 비대칭, 뺄 요소(망토, 불꽃 등) | `brief.md` | |
| 2 픽셀화 판단 | 일러스트이거나, 등신이 목표와 1 넘게 다르거나, 2도트 미만 요소가 실루엣 키에 있으면 픽셀 시안을 먼저 만든다 | 판단 기록 | |
| 3 레퍼런스 | 기준: 체형 1명(키·비율), 얼굴 1명(얼굴·눈). 요소별: 목·다리·신발·장식마다 1명. 후보를 나란히 놓고 측정값으로 고른다 | 목표표, 요소표 | ① |
| 4 그림체 기준 | **텍스트로 새로 만들지 않는다.** 레퍼런스에 가까운 완성 스프라이트를 고르거나 만든다. 고른 이유와 측정값(구간 폭, 외곽선, 밀도)을 기록한다 | 그림체 기준 이미지 또는 캐릭터 ID | |
| 5 정면 생성 | 그림체 기준 + 시안(뺄 요소 지운 정면). 설명은 넣을 것·뺄 것만 짧게. 비율이 어긋나면 비율 맞는 완성 스프라이트를 편집 입력으로 | 정면 후보 2~3안 | |
| 6 최소 정리 | 알파, 셀 맞춤, 1도트, 눈, 공용 팔레트. 그림이 좋아지는 것만 | 정면 마스터 | ② |
| 7 방향 | 정면 마스터를 첫 프레임으로 회전. 떨어진 덩어리, 동·서 뒤바뀜, 키 차(3 이하) 확인 | 8방향 | ③ |
| 8 마무리 | Idle 4프레임 → `check_sprite.py`, `silhouette_check.py` 오류 0 → 엔진 낮·밤 캡처(밝기 규칙 검증 포함) | 시트, 캡처 | ④ |

판정 순서: **그림을 먼저 보고(4배 이상 확대, 실루엣, 게임 배율), 그다음 수치.** 수치만 통과한 실패작이 반복해서 나왔다.

## 6. PixelLab 입력별로 실제 바뀌는 것 (2026-11-11~12 시험)

| 입력 | 따른 것 | 따르지 않은 것 | 근거 |
|---|---|---|---|
| 그림체 기준 캐릭터/이미지 | 몸 비율, 외곽선 방식, 명암, 안쪽 밀도, 폭 배분 | | A~J 모두 style_v1 → 다리 12행. K(첨부본 기준) → 폭 배분이 첨부본 쪽으로 |
| 시안 이미지 (pro `concept_image_url`) | 색, 큰 장식, 옷 구성 | 비율 | 일러스트(A·B), 시트(C·D), 비율 가이드(E·F) 모두 다리 12행 |
| 설명 문장 | 장식 유무(가터, 신발 끈, 머리색 구간) | 비율, 폭, 외곽선 색, 밝기, 눈 구조. 원래 있던 요소가 사라지기도 함 | J |
| 편집 입력 (`edit_image` 참조 모드) | 비율, 자세 — 입력이 완성된 스프라이트일 때만 | 단색 블록아웃은 참조에 덮임 | G 성공, H 실패 |
| 편집 참조 이미지 | 옷, 선, 색 | 원치 않는 변화도 따라옴(머리색) | G |
| 첫 프레임 (`pro_flash first_frame_url`) | 정면 픽셀 그대로 | 다른 방향에 떨어진 덩어리, 동·서 뒤바뀜이 생김 | 8방향 회전 |

### 호출 예시

```text
# 정면 생성(pro): 그림체 기준 + 시안. 크기 52 → 결과는 52x52, 정리 단계에서 64x80 셀로
create_character(mode="pro", size=52, style_character_id=<ID> 또는 style_image_url=<upload>,
                 concept_image_url=<upload: 뺄 요소 지운 정면>, description=<넣을 것·뺄 것만>)   # 10생성

# 정면 생성(pro_flash): 그림체 이미지 + 설명. 시안 이미지 칸이 없다
create_character_pro_flash(width=64, height=80, style_image={"url": <upload>}, description=...)  # 약 6생성

# 비율 유지 + 옷 입히기
edit_image(image_urls=[<비율 맞는 완성 스프라이트>], reference_image_url=<옷 참조>, seed=7)    # 10생성

# 8방향(정면은 그대로)
create_character_pro_flash(first_frame_url=<정면 마스터 64x80>, description=<짧게>)            # 1생성
```

- 로컬 파일은 `get_upload_url` → `curl -F "file=@x.png" <url>` → `upload:<id>`. 3일 지나면 만료된다
- pro_flash 회전 결과는 80×80 캔버스, 정면 마스터가 8~71열에 그대로 들어간다
- pro_flash는 대기열 때문에 15분까지 걸린 적이 있다. `wait_for_jobs(timeout_seconds=540)`로 기다린다
- 비용은 생성 전에 사용자에게 알리고, 큰 배치는 확인받는다

## 8. 하지 말 것 (시험에서 나빠진 것)

| 하지 말 것 | 결과 |
|---|---|
| 그림체 기준을 텍스트로 만들기 | 레퍼런스와 무관한 그림체가 전체 결과를 정함 |
| 시안이나 설명으로 비율 맞추기 | 효과 없음 |
| 행을 빼거나 늘려 비율 맞추기 (2~3행 초과) | 무늬가 눌림 |
| 흰색 일괄 압축, 연보라로 섞기 | 회보라로 가라앉거나 보라로 물듦 |
| 전체 외곽선을 한 번에 다른 색으로 | 안쪽 선과 섞여 형태가 흐려짐 |
| 꼬리를 비율로 다시 샘플링해 폭 줄이기 | 꼬리가 가는 줄이 됨 |
| 단색 블록아웃을 편집 입력으로 | 참조에 덮임 |

## 9. master_v1(이전 Hiyori, 레퍼런스에 가까웠던 결과)에서 배운 것

- 정면은 생성 → 편집 참조(입력 = 비율 맞는 정면, 참조 = 옷이 잘 나온 생성) → 좌표 스크립트 약 15개로 사람이 완성했고, PixelLab에는 첫 프레임 회전만 맡겼다
- 요소마다 FFBE 한 명을 골라 도트 구성을 옮겼다: 목(Aileen·Amelia·Dark Fina), 다리(Amelia), 신발(Fina·Amelia·Lunera), 망토(Bran·Lunera·Ayaka·Charlotte), 눈(Dark Fina)
- 레퍼런스처럼 보인 이유는 다리 길이가 아니라 폭 배분이다(망토 A라인, 몸에 붙은 꼬리, 촘촘한 안쪽). 구간별 최대 폭/키(머리/가슴/허리/무릎/발): master_v1 0.51/0.90/0.98/0.90/0.82, Fina 0.36/0.52/0.56/0.32/0.22, 생성 원본 E 0.56/0.72/0.88/0.88/0.80
